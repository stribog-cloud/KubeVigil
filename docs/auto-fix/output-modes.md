# Output Modes

The `kubevigil fix` command supports multiple output modes for different workflows. The default is `diff`, which shows a unified diff of planned changes. Alternative modes generate kubectl commands, Helm values, Kustomize overlays, Markdown reports, and GitOps pull requests.

## Diff (Default)

Shows a unified diff of every file that would be modified. Removed lines are prefixed with `-`, added lines with `+`. On terminals, the diff is ANSI-colored: red for removals, green for additions, cyan for hunk headers.

```bash
kubevigil fix ./manifests/
```

Example output:

```diff
--- a/manifests/deployment.yaml
+++ b/manifests/deployment.yaml
@@ -18,6 +18,8 @@
       containers:
       - name: app
         image: myapp:v1.2.3
+        securityContext:
+          privileged: false
```

When non-safe fixes are included (at `--risk-level moderate` or `aggressive`), impact warnings are printed inline after the diff:

```
# IMPACT (likely_safe): Containers that require root will fail to start.
# IMPACT (potentially_breaking): Applications exceeding limits will be throttled or OOMKilled.
```

Disable color with `--no-color`:

```bash
kubevigil fix ./manifests/ --no-color
```

## kubectl

Generates `kubectl patch` commands organized by namespace. These commands are printed to stdout and never executed. You can review them, modify them, and apply them through your normal workflow.

```bash
kubevigil fix ./manifests/ -o kubectl
```

Example output:

```bash
# KubeVigil kubectl patch commands
# Risk level: safe

# --- Namespace: default (3 patches) ---

# Fix: Disables privileged mode. (check: privileged, risk: safe)
kubectl patch deployment my-app -n default --type=strategic -p '{"spec":{"template":{"spec":{}}}}'

# Fix: Disables privilege escalation. (check: privilege-escalation, risk: safe)
kubectl patch deployment my-app -n default --type=strategic -p '{"spec":{"template":{"spec":{}}}}'
```

The `kubectl` output mode does not require `--apply` -- it generates commands from the dry-run plan.

## Helm Values

Generates a `security-values.yaml` file for Helm chart hardening. Maps fixable checks to their corresponding Helm values structure.

```bash
kubevigil fix ./manifests/ -o helm-values
```

Example output:

```yaml
# KubeVigil Security Values
# Generated for Helm chart hardening
# Risk level: safe
#
# Usage: helm upgrade <release> <chart> -f security-values.yaml

# Security Context
securityContext:
  privileged: false
  allowPrivilegeEscalation: false

# Service Account
serviceAccount:
  automountServiceAccountToken: false
```

Potentially breaking values are commented out by default with a warning:

```yaml
# Resources (potentially breaking - verify before applying)
# resources:
#   limits:
#     cpu: 500m
#     memory: 256Mi
#   requests:
#     cpu: 100m
#     memory: 128Mi
```

To apply these values:

```bash
kubevigil fix ./manifests/ -o helm-values > security-values.yaml
helm upgrade my-release my-chart -f security-values.yaml
```

The `helm-values` output mode does not require `--apply`.

### Helm-Managed Resource Detection

KubeVigil automatically detects resources managed by Helm (via `app.kubernetes.io/managed-by: Helm` labels or `helm.sh/` prefixed labels). When detected, it prints a suggestion:

```
Warning: 3 file(s) contain Helm-managed resources.
Consider using --output helm-values instead of patching manifests directly.
```

## Kustomize

Generates a Kustomize overlay directory with strategic merge patches for all fixable findings. The overlay includes a `kustomization.yaml` and one patch file per resource.

```bash
kubevigil fix ./manifests/ --kustomize ./security-overlay/
```

This creates:

```
./security-overlay/
  kustomization.yaml
  deployment-default-my-app.yaml
  deployment-default-frontend.yaml
```

Example `kustomization.yaml`:

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

# Generated by KubeVigil fix (risk level: safe)
# Apply with: kubectl apply -k <overlay-dir>

patches:
  - path: deployment-default-frontend.yaml
  - path: deployment-default-my-app.yaml
```

To apply:

```bash
kubectl apply -k ./security-overlay/
```

The `--kustomize` flag does not require `--apply` -- it generates the overlay from the dry-run plan and exits.

### Kustomize Detection

When KubeVigil detects an existing `kustomization.yaml` or `kustomization.yml` in the scanned directory, it prints a suggestion:

```
Warning: Kustomize configuration detected.
Consider using --kustomize <dir> to generate a Kustomize overlay instead.
```

## Markdown Report

When `--apply` is used, a Markdown fix report is automatically generated and saved in the backup directory as `FIX-REPORT.md`. Use `--report` to write it to a custom path:

```bash
kubevigil fix ./manifests/ --apply --report fix-changelog.md
```

The report includes:

- **Summary**: Files scanned, modified, failed; findings applied and skipped; risk breakdown
- **Changes by File**: Per-file list of applied fixes with check ID, safety level, and description
- **What Could Break**: Impact warnings for non-safe fixes that were applied
- **Skipped Findings**: Grouped by reason (system namespace, risk level, filtered, etc.)
- **Manual Remediation**: Guidance for findings that cannot be auto-fixed
- **Restore Instructions**: Backup directory path and restore commands

## GitOps PR

The `--git-pr` flag creates a Git branch, commits the patched files, pushes to the remote, and opens a pull request. Requires `--apply` and either the GitHub CLI (`gh`) or GitLab CLI (`glab`) to be installed and authenticated.

```bash
kubevigil fix ./manifests/ --apply --yes --git-pr
```

This:

1. Creates a branch named `kubevigil/fix-YYYYMMDD-HHMMSS`
2. Stages all modified files
3. Commits with a message like `fix: apply 12 KubeVigil security fixes across 4 files`
4. Pushes the branch to origin
5. Creates a PR/MR with the fix report embedded in a collapsible `<details>` section

```
Pull request created: https://github.com/org/repo/pull/42
```

For GitHub, it uses `gh pr create`. For GitLab, it uses `glab mr create`. KubeVigil auto-detects which CLI is available.

## Verify Mode

The `--verify` flag re-scans all modified files after fixes are applied and reports how many findings were resolved:

```bash
kubevigil fix ./manifests/ --apply --verify
```

Verification output:

```
Verification Results
--------------------
Fixable before:     12
Fixable after:       0
Resolved:           12

All fixable findings resolved.
```

If findings remain after fixing:

```
Verification Results
--------------------
Fixable before:     12
Fixable after:       2
Resolved:           10

2 fixable findings remain:
  manifests/deployment.yaml: run-as-root, read-only-rootfs
```

When `--verify` finds remaining findings, the exit code is `1` instead of `0`. This is useful in CI to confirm that fixes actually resolved the issues.

## Combining Modes

Some output modes can be combined:

```bash
# Apply fixes, generate Kustomize overlay, and create a PR
kubevigil fix ./manifests/ --apply --yes --kustomize ./security-overlay/ --git-pr

# Apply fixes with custom report path and verification
kubevigil fix ./manifests/ --apply --report changelog.md --verify
```

Note that `kubectl` and `helm-values` output modes (`-o kubectl`, `-o helm-values`) are standalone -- they print to stdout and exit without requiring `--apply`. The `--kustomize` flag also generates output and exits without requiring `--apply`.
