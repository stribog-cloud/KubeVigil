## Objectives

### 1. Kustomize Overlay Generator (`internal/fix/kustomize_gen.go`)

`kubevigil fix --kustomize ./overlays/security/ ./manifests/` generates a Kustomize overlay:

```
./overlays/security/
├── kustomization.yaml
├── deployment-web-security-patch.yaml
├── deployment-api-security-patch.yaml
└── statefulset-db-security-patch.yaml
```

The `kustomization.yaml`:
```yaml
# Generated by KubeVigil — security hardening overlay
# Date: 2026-02-17T14:30:22Z
# Risk level: safe
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

patches:
  - path: deployment-web-security-patch.yaml
  - path: deployment-api-security-patch.yaml
  - path: statefulset-db-security-patch.yaml
```

Each patch file is a strategic merge patch:
```yaml
# KubeVigil security patch for Deployment/web-frontend
# Fixes: privileged, privilege-escalation, read-only-rootfs
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-frontend
  namespace: production
spec:
  template:
    spec:
      containers:
        - name: web
          securityContext:
            privileged: false
            allowPrivilegeEscalation: false
            readOnlyRootFilesystem: true
```

Implementation notes:
- Group fixes by resource (one patch file per resource)
- Use strategic merge patch format (the Kustomize default)
- Include helpful comments documenting what each patch fixes
- Detect if Kustomize structure already exists and warn about conflicts
- Handle multi-container pods correctly (each container listed separately)

### 2. Helm Values Generator (`internal/fix/helm_gen.go`)

`kubevigil fix --output helm-values ./manifests/` generates a `security-values.yaml`:

```yaml
# KubeVigil security values override
# Generated: 2026-02-17T14:30:22Z
# Apply with: helm upgrade <release> <chart> -f security-values.yaml

# Common Helm chart value patterns for security hardening
podSecurityContext:
  runAsNonRoot: true
  # runAsUser: 65534  # Uncomment and set appropriate UID

securityContext:
  privileged: false
  allowPrivilegeEscalation: false
  readOnlyRootFilesystem: true
  capabilities:
    drop:
      - ALL

resources:
  limits:
    cpu: "500m"     # Adjust based on workload
    memory: "256Mi" # Adjust based on workload
  requests:
    cpu: "100m"
    memory: "128Mi"

serviceAccount:
  automountServiceAccountToken: false
```

Implementation:
- Map common Helm chart value paths:
  - `securityContext.*` → container security context
  - `podSecurityContext.*` → pod-level security context
  - `resources.limits.*`, `resources.requests.*` → resource constraints
  - `serviceAccount.automountServiceAccountToken` → SA token mount
  - `image.pullPolicy` → image pull policy
- Detect Helm-managed resources by labels and use chart-specific value mappings where possible
- Add comments indicating what each value fixes
- Mark values that need manual tuning (resource limits, UIDs) with `# Adjust` comments
- Values that are potentially breaking are commented out with explanation

### 3. Fix Report Generator (`internal/fix/report.go`)

Generate a detailed Markdown changelog after every fix:

```go
func GenerateFixReport(summary *FixSummary, plan *FixPlan) ([]byte, error)
```

Report format follows Section 7.5 of the features spec. Saved to `<backup-dir>/FIX-REPORT.md`.

Include:
- Header with timestamp, risk level, summary stats
- Changes grouped by file (each file lists its fixes with check ID, severity, risk, description)
- "What Could Break" warnings for likely-safe and potentially-breaking fixes
- Skipped items grouped by reason (system namespace, risk level, manual-only)
- Manual remediation guidance for manual-only findings
- Restore instructions referencing the backup directory

### 4. Verify (Re-Scan) Feature

When `--verify` is passed with `--apply`:

1. After all fixes are applied, re-scan the same paths
2. Compare: findings resolved, findings remaining, new findings introduced
3. Report results:

```
Verification Results:
  Findings before fix:  65
  Findings after fix:   28
  Resolved:             37
  Remaining:            28 (12 manual-only, 8 risk-filtered, 8 system-ns)
  New findings:          0

✅ All applied fixes verified — no regressions introduced.
```

Exit code 1 if `--verify` finds that applied fixes didn't actually resolve findings (indicates a bug in the patcher).

### 5. GitOps PR Generator (`internal/fix/gitops.go`)

`kubevigil fix --apply --git-pr ./manifests/` creates a Git branch, commits fixes, and opens a PR:

```go
func CreateGitOPSPR(config GitPRConfig) error

type GitPRConfig struct {
    BranchName  string // Default: "kubevigil/security-fixes-<timestamp>"
    CommitMsg   string // Default: "fix(security): auto-remediate KubeVigil findings"
    PRTitle     string // Default: "KubeVigil: Security Hardening — N fixes applied"
    PRBody      string // Generated from fix report
    BaseBranch  string // Detected from git (usually main/master)
}
```

Workflow:
1. Detect `gh` (GitHub CLI) or `glab` (GitLab CLI) availability
2. Check for clean git state (warn if dirty)
3. Create branch: `git checkout -b kubevigil/security-fixes-<timestamp>`
4. Stage fixed files: `git add <modified-files>`
5. Commit with descriptive message including fix summary
6. Push branch: `git push -u origin <branch>`
7. Create PR/MR: `gh pr create` or `glab mr create` with fix report as description

Error handling:
- No `gh`/`glab` → error with install instructions
- Dirty git state → warning, proceed anyway (user may want to include other changes)
- Push fails → error with manual instructions ("Run: git push -u origin <branch>")
- PR creation fails → error with URL to create manually

### 6. Helm/Kustomize Detection Warnings

Wire into the fixer:

- When `app.kubernetes.io/managed-by: Helm` or `helm.sh/chart` labels detected:
  ```
  ⚠️  Helm-managed resources detected. Direct manifest patches will be
     overwritten on next `helm upgrade`. Consider:
     kubevigil fix --output helm-values ./manifests/
  ```
  
- When `kustomization.yaml` found in target directory:
  ```
  ⚠️  Kustomize structure detected. Patching base manifests may conflict
     with overlays. Consider:
     kubevigil fix --kustomize ./overlays/security/ ./manifests/
  ```

These are warnings, not blocks. The operator can proceed with direct patching if they choose.
